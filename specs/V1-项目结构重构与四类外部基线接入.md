## 1. 当前结构与主要问题

### 1.1 已核实的代码事实

1. `models/hadt_nq.py` 是原始 HADT-NQ 模型入口，调用 RevIN、patch embedding、Transformer encoder、horizon deformable decoder 和 noncrossing head。
2. `models/paper_baselines.py` 并非单纯的 HADT 层文件，其中还包含直接预测模型、密集注意力解码层及内部对照工厂。
3. `models/architecture_search.py` 混合了候选表、模型构造、MLP/CNN 层及验证集选择逻辑。
4. `losses/quantile_loss.py`、`metrics/interval_metrics.py` 分别存放损失与评估工具；多个训练、测试和脚本模块直接依赖旧路径。
5. `experiments/runner.py` 的模型构造固定为 HADT-NQ；`utils/config.py` 的校验默认要求所有模型都有 HADT 的 patch/head/horizon 字段。
6. 训练默认随机抽变量，验证和测试默认把变量切成多块分别前向；可视化先挑部分变量再前向，并假定模型一定返回 HADT 的 offsets/positions 等辅助量。
7. 当前检查点保存 `state_dict`，而不是完整模型对象。这有利于纯文件迁移，但必须保持 HADT 模块属性名和参数键名兼容。

### 1.2 本次要解决的问题

- 模型主干、专用层和公共代码边界不清。
- 缺少 PatchTST、TimeMixer、DLinear、iTransformer 外部模型主干。
- 将已有的内部 Patch-NQ/Linear-NQ 当成 PatchTST/DLinear 会造成错误实验归因，必须区分。
- 原有通道独立执行方式无法直接用于跨变量建模的 iTransformer，以及启用变量耦合的 TimeMixer。
- 外部模型通常输出点预测，必须明确分位数任务适配方式和偏离官方实现的范围。

## 2. 目标与非目标

### 2.1 必须达到的目标

1. `models/` 放完整模型主干，每个外部模型一个入口文件。
2. `layers/` 按模型组织专用网络模块。
3. `utils/` 放模型通用组件，包括损失、指标、归一化、有序分位数转换、配置和种子等。
4. 新增四个真实外部主干：PatchTST、TimeMixer、DLinear、iTransformer。
5. 统一数据、训练、测试、最佳模型保存及预测图输出接口。
6. 保留原始 HADT、选中 MLP 配置和内部对照，保证旧实验可重建、旧检查点可加载。
7. 保留原来进度条、早停、验证集选模和全变量测试能力。
8. 每次新实验记录具体模型、适配方式、完整配置、来源版本与代码指纹。

### 2.2 本次不包含

- 不顺便增加校准损失、改良注意力、改变 HADT 公式或替换既有指标定义。
- 不自动改写论文主张或将新结果混入旧结果表。
- 不下载全套官方训练框架替换本项目的数据管线。
- 不默认开展七数据集全量调参和训练；本规范要求功能验证及有限集成试跑，正式全量实验另行明确预算。
- 不复制其他版本的 TimeMixer++、预训练模型或同名简化实现冒充指定基线。

### 5.1 官方来源

| 模型 | 作者仓库 | 本次接入所依据的入口 |
|---|---|---|
| PatchTST | <https://github.com/yuqinie98/PatchTST> | `PatchTST_supervised/models/PatchTST.py`、`PatchTST_supervised/layers/PatchTST_backbone.py`；监督学习版本 |
| TimeMixer | <https://github.com/kwuking/TimeMixer> | `models/TimeMixer.py`；long-term forecasting 分支 |
| DLinear | <https://github.com/cure-lab/LTSF-Linear> | `models/DLinear.py` |

上述入口已在规范编写时查阅。实施时先固定完整上游 commit SHA，再取代码并记录许可、依赖及所有本地改动；本规范不把会变化的 `main` 当成已锁定版本，也不填写未经核验的 SHA 或许可证名称。

### 5.2 不可丢失的核心结构

- **PatchTST**：保留 channel-independent patch tokenization、末端 padding 选择、位置编码、原生注意力/归一化设置和 flatten forecast head。不能直接复用当前 HADT 的41-token配置后声称是官方 PatchTST；token数取决于该模型自己的 padding 配置。
- **TimeMixer**：保留多尺度输入、季节/趋势分解、季节由细到粗及趋势由粗到细的混合、各尺度预测分支与融合。明确 `channel_independence`、下采样方法和层数，不引入未来真实值。
- **DLinear**：保留移动平均分解，以及季节/趋势两条独立线性映射后相加；实现共享映射与 `individual` 选项。不能用当前无分解的 Linear-NQ 冒充 DLinear。
- **iTransformer**：保留 inverted embedding，将变量作为 token，以变量轴注意力建模变量关系，再投影到预测长度；不能改成 HADT 的通道独立 patch encoder。

实施时记录相对官方设置的差异；不将所有模型都套上 HADT 的3层编码器、RevIN或可变形解码器。仅迁入预测任务必需代码与依赖，保留归属说明，不额外引入官方整套数据/训练系统。

## 6. 点预测与区间预测的统一适配协议

### 6.1 两种显式输出模式

1. `output_mode: point`：输出 `[B,H,C]`，使用 MSE，主要用于上游主干保真检查；不能计算或伪造区间指标。
2. `output_mode: quantile`：输出 `[B,H,C,7]`，使用项目现有七分位数 pinball，作为后续区间任务比较的默认模式。

外部模型的论文表格名称必须注明 `PatchTST-NQ`、`TimeMixer-NQ`、`DLinear-NQ`、`iTransformer-NQ`，说明“官方主干的本地分位数适配”，不能称为官方原版概率模型或直接复用官方点预测排行榜数值。

### 6.2 保留点预测头，统一追加现有分位数头

```text
历史输入 [B,L,C]（训练集标准化尺度）
    ↓
原生点预测模型（保留主干、预测头、多分支融合、原生逆归一化）
    ↓
点预测 p [B,H,C]（已恢复到训练集标准化尺度）
    ↓ permute + reshape + 增加特征维，不引入可学习层
标量特征 [B×C,H,1]
    ↓
MedianAnchoredNonCrossingHead(d_model=1)
    ↓
有序分位数 [B×C,H,7]
    ↓ 恢复维度
最终输出 [B,H,C,7]
```

五个待比较模型的说明：

| 模型 | 分位数头之前的输出 | 分位数头 |
|---|---|---|
| HADT-NQ | 已有解码特征 `[B×C,H,D]` | 现有类，保留现有输入宽度和逆RevIN顺序 |
| PatchTST-NQ | 原始 PatchTST 点预测 `[B,H,C]` | 同一类，`d_model=1` |
| TimeMixer-NQ | 完成多尺度预测融合后的点预测 `[B,H,C]` | 同一类，`d_model=1` |
| DLinear-NQ | 季节/趋势点预测相加后的结果 `[B,H,C]` | 同一类，`d_model=1` |
| iTransformer-NQ | 原生变量token投影与逆归一化后的点预测 `[B,H,C]` | 同一类，`d_model=1` |

“相同输出头”指复用同一 `MedianAnchoredNonCrossingHead` 实现、相同七分位数、初始化规则、最小间隔及正累积间隔公式。每个模型有自己独立训练的头参数，不在模型之间共享权重。因输入宽度不同，投影层参数量不同，不宣称参数预算完全一致。

实施伪代码（仅作为接口规范）：

```python
p = self.point_model(x)  # [B,H,C]，不接收未来真实目标
b, h, c = p.shape
features = p.permute(0, 2, 1).reshape(b * c, h, 1)
q = self.quantile_head(features)  # 同一现有类，输入宽度为1
q = q.reshape(b, c, h, 7).permute(0, 2, 1, 3).contiguous()
return q
```

包装逻辑可抽取为 `utils/quantile_heads.py` 的通用组件；完整外部模型入口仍分别位于 `models/patchtst.py`、`models/timemixer.py`、`models/dlinear.py`、`models/itransformer.py`。

#### 模型适配边界

- 四个模型均保留原始点预测头及其输出维度，不把预测头扩为七参数。
- DLinear 两分支仍分别输出H个点后相加；TimeMixer完成各尺度与残差点预测融合后，才追加一次统一头。
- 不额外添加 `Linear(1,D)`、MLP、预测步embedding或变量特定头扩展标量输入；不接入 HADT 解码器。
- 保留原生点模型归一化和逆变换，包括原生affine设置；追加头位于原生逆归一化之后，不因分位数排序要求修改原模型。

### 6.3 公共输出头的精确定义

迁移前来源：`models/noncrossing_head.py` 的 `MedianAnchoredNonCrossingHead`；迁移后唯一实现：`utils/quantile_heads.py`。

- `projection = Linear(input_dim, 7)`。
- 第一个原始输出为中位数，另外六个输出经 `softplus + min_gap` 得到正间隔。
- 下侧累计相减再反转，上侧累计相加，输出 `[q05,q10,q25,q50,q75,q90,q95]`。
- `min_gap=1e-4`、`initial_gap=0.55`，小随机投影权重及间隔bias初始化与现有实现一致。
- 外部模型 `input_dim=1`，HADT保留原 `input_dim=D`；不改变旧 HADT 的参数键、检查点和计算结果。
- `q50` 是追加输出头对 `p` 的可学习映射，**不强制等于原始点输出 `p`**；若强制中位数等于点输出，就不是当前同一个头，首版不这样修改。
- 不通过排序、固定宽度或复制点预测生成分位数。

### 6.4 端到端训练与尺度

- 四个适配模型及其追加头从初始化起端到端优化现有七分位数 pinball loss，梯度必须穿过追加头到达原始预测头及主干。
- 不新增 MSE辅助损失，不默认预训练或冻结点模型；point模式MSE仅服务独立保真验证。
- 七分位数集合、loss归约、验证pinball选模、测试指标及数据切分与现有区间任务保持一致。
- 外部点模型返回值必须处在训练集标准化尺度；追加头输出也处于该尺度，之后只由评估器撤销全局scaler。不得重复撤销模型内部归一化。
- HADT现有头在RevIN归一化特征上计算，再撤销RevIN，保持原样。外部模型的追加头在原生点模型已逆归一化后计算：虽然类和超参数相同，两者的输入表示和间隔所处坐标不同，实验说明必须如实记录。
- 所有外部模型仍遵守 第7节的变量能力策略，尤其 iTransformer 不允许拆变量独立前向。

### 6.5 公平性与解释边界

这项设计统一了输出头实现、排序约束和训练目标，同时完整保留外部点预测模型的原始预测流程，属于本轮主比较协议。

但外部追加头只读取每个变量每个未来步的一个标量，HADT头读取D维特征；因此表达能力和可利用的不确定性信息并不相同。例如两个样本同一位置的点输出相同时，共享的确定性标量头会返回相同的七分位数，无法仅凭额外历史信息区分其不确定性。

不得把“同一头类”表述为所有因素都完全相同，不把适配后的结果直接说成官方原版模型的区间效果。若后续研究需要“原生高维特征接统一头”或“所有模型统一标量瓶颈”的对照，需另写规范并独立标注，本次不自行实施。

### 6.6 时间特征与尺度

- 首版统一只使用现有 CSV 的历史数值变量，不新增时间特征；官方允许的时间标记入口显式传 `None`，关闭需要未来时间标记的 TimeMixer 分支，并记录这一设置。
- 所有模型输入为训练集统计量标准化后的 `[B,L,C]`；区间模式输出同一全局标准化尺度。
- 模型内部使用的窗口归一化需要在返回前撤销；外部 scaler 逆变换由评估和绘图工具执行。
- 不改变既有按时间比例划分的语义；结果必须注明是本项目划分，不等价于官方固定月份划分。

## 7. 模型接口、注册及变量策略

### 7.1 构建与能力声明

统一构建入口：`build_model(config, pred_len, n_vars)`，位于 `utils/model_registry.py`。

注册名：`hadt_nq`、`patchtst`、`timemixer`、`dlinear`、`itransformer`；内部控制名独立注册，不能与外部模型混同。

模型主接口：

```python
forward(x, return_aux=False, intervention=None)
# 普通调用：返回预测 Tensor
# return_aux=True：返回 (prediction, aux_dict)
```

能力信息至少包括：模型标识、输出模式、是否允许任意变量子集、是否允许变量分块前向、辅助诊断键、支持的 intervention。能力随配置实例确定，不能仅按类名猜测。

- 未支持的非空 intervention 必须明确报错，不能静默忽略。
- `return_aux=True` 可返回空字典；外部模型不必伪造 offsets、patch tokens 或 HADT 注意力。
- 模型工厂不要求 DLinear 暴露 `n_heads/n_patches/max_horizon` 等无关属性。
- 数据读取后传入真实 `n_vars`，保存稳定的变量名顺序；固定维度模型验证 `enc_in/c_out` 与任务一致，本次仅支持所有输入变量对应输出的 M→M 任务。

### 7.2 必须修正的变量处理

| 模型/配置 | 默认训练前向 | 默认验证/测试前向 |
|---|---|---|
| 既有 HADT 与共享通道独立内部对照 | 保留已有变量抽样策略 | 可按变量分块，覆盖全部变量 |
| PatchTST-NQ、DLinear-NQ | 外部比较默认全变量；仅通过能力验证的共享头配置可选抽样 | 只有数学上独立且不绑定变量位置时才允许分块 |
| iTransformer-NQ | **全部变量共同进入主干** | **全部变量共同进入主干** |
| TimeMixer-NQ | 首版默认全变量；能力按具体模式验证 | 首版默认全变量，不因 `channel_independence=1` 就直接假定可分块 |

- iTransformer 不得沿用随机16变量训练或8变量独立推理，否则改变注意力上下文。
- TimeMixer 即使使用通道独立模式，原生通道数绑定、归一化参数、卷积下采样和 reshape 也可能限制分块；只有全部检查并通过等价性测试才开放。
- DLinear `individual=True` 和 PatchTST 独立变量头不能把子块当作从0开始的变量重新调用；首版禁止变量抽样/分块，不提供未经验证的 channel-index 映射捷径。
- 变量策略采用 `auto` 时解析为安全能力；用户显式要求非法抽样/分块时校验报错，不能静默改变实验。
- 多变量模型显存不足时降低样本批量、使用合适的时间/计算块或梯度累积；不得拆变量破坏语义。不能运行则记录 OOM/失败，不生成成功结果。
- 可视化必须先以完整所需变量上下文推理，再挑选展示变量。`max_channels` 只控制保存/展示，不改变跨变量模型的输入。

## 8. 配置与执行入口

示意接口（具体官方主干超参数在实施时固定并写入各模型配置）：

```yaml
model:
  name: itransformer
  output_mode: quantile
  quantile_head: median_positive_gap
  quantile_adapter: post_point_shared_head
  quantiles: [0.05, 0.10, 0.25, 0.50, 0.75, 0.90, 0.95]
  params:
    d_model: 128
    n_heads: 8
    e_layers: 2
    d_ff: 256
    dropout: 0.1
training:
  channel_policy: auto
evaluation:
  channel_policy: auto
```

- 公共字段与 `model.params` 中模型专用字段分别校验。DLinear 不需要 patch 参数；TimeMixer 需要检查下采样后长度；PatchTST 检查 padding 后 patch 数；iTransformer 检查 head 维度和输入变量数。
- `params` 中未知或未使用键报错，不能把 HADT 参数悄悄传给其他模型。
- 旧 YAML 未提供 `model.name` 时仍解析为原 HADT，旧默认配置、旧 MLP 选择记录和历史实验构建结果不变。新格式可显式指定 HADT 编码器类型，但不能将原默认改为 MLP。
- 每个外部模型可通过 `main.py --mode single --config configs/baselines/<model>.yaml --dataset ETTh1 --pred_len 96 --seed 2024` 运行；必要时增加 CLI 模型覆盖参数，但不以 CLI 隐式覆盖模型专用配置。
- `smoke` 模式支持选择模型；旧无参数 smoke 行为兼容。
- 旧 `_build_model(config,pred_len)` 可作为明确只服务旧 HADT 脚本的兼容入口；新公共 runner 使用统一工厂，避免改变旧搜索候选的构造语义。
- 正式运行使用 `djjTF`。训练验证默认物理 GPU3：`CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=3`，进程内为 `cuda:0`。实施阶段只执行第10节的有限验证，不启动未经安排的正式全量实验。

## 9. 训练、评估、可视化与实验公平性

### 9.1 统一运行链路

- 数据加载→解析模型配置与能力→构建模型→训练进度条→验证→保存最佳检查点→重新加载→全测试集评估→保存预测图。
- 点模式按验证 MSE 选模；量化模式按验证 pinball 选模，不能以测试结果选检查点。
- 保留梯度裁剪、早停、调度器和已有日志；梯度累积如启用，明确批量、有效批量及调度器语义。
- 区间指标仍按既有定义计算 pinball、CrossingRate、PICP50/80/90、PINAW及Winkler；未定义的点模式区间指标不输出假值。

### 9.2 产物与恢复

新实验目录示意：

```text
outputs/baseline_comparison/<model>/<variant>/<dataset>/H<h>/seed<s>/
  resolved_config.json
  source_manifest.json
  best_checkpoint.pt
  train.log
  history.csv
  metrics.json
  horizon_metrics.csv
  complete.json
  figures/forecast_samples.npz
  figures/predictions/...
```

- `resolved_config` 包含原始与解析配置、模型版本、输出头、变量策略、输入变量名、训练 scaler、超参数及来源；完整结果身份还包括数据/代码指纹。
- 目录不是唯一正确性判断。已有完成标记与当前配置/源码/数据不一致时拒绝覆盖，改用新实验标识。
- `complete.json` 仅在检查点、完整测试指标及必要产物验证通过后原子写入；中断、OOM、NaN、缺种子不能算完成。
- 新检查点保存 `model_name`、variant、schema/version、输出模式、配置及必要通道元数据；对不匹配模型加载应报错。
- 原 HADT 的权重层级和 `state_dict` 键名保持不变；旧检查点缺新元信息时只走明确的 legacy HADT 路径，保持 strict 加载。

### 9.3 画图与浏览页

- 预测图统一支持真实值、中位数及50/80/90%区间，窗口预先固定为首/中/末，图上说明模型和适配版本。
- 点模式只画真实值和点预测，不画伪区间。
- 按辅助量能力生成模型诊断：HADT 可画采样和偏移；其他模型只画真实存在的表示/分解/注意力，不要求键完全一致。
- `scripts/plot_run_forecasts.py` 适配新实验记录与旧记录；浏览页增加明确的 model/variant 标识，既有候选筛选不失效。

### 9.4 公平比较原则

- 同一正式比较使用相同原始数据、切分、历史长度、预测长度、七分位数及评估总体；验证集拟合/选择策略记录完整。
- 不能强制所有模型用相同隐藏层超参数后声称充分调优；正式比较预先定义相当的调参预算与训练上限，记录各模型实际预算。
- 原生归一化、变量耦合、padding等差异显式报告；不为了统一外观而删除核心结构。
- 若 HADT 保留历史抽样训练、外部模型用全变量，必须标明这是实际执行策略差异；需要严格预算对照时另开全变量 HADT 组，不能把旧实验当作该组。
- 不将不同数据集的全局标准化损失直接当成相同尺度做总分；总体结论按每数据集/预测长度的相对变化或名次报告。
- 论文新增结果待真实运行后再写入，不预填分数，不称四个外部模型已经跑完。

## 10. 实施阶段与验收条件

### 阶段A：纯迁移与历史兼容

1. 迁移现有专用层、公共损失/指标/归一化与实验工厂；全仓库更新引用。
2. 保留 HADT 默认计算与参数键，更新指纹生成脚本以适应新路径，不修改历史指纹。
3. 跑原有测试，并用同一个既有 checkpoint、固定输入在 `eval()` 模式比较迁移前后输出和关键辅助量。
4. 验收：CPU同环境目标输出完全一致；GPU考虑kernel差异预先采用 `atol=1e-6, rtol=1e-5`，差异超限需定位。state_dict键集合一致，strict加载成功。

### 阶段B：注册与通道安全执行

1. 引入模型注册、模型专用配置校验及能力驱动的训练/验证/测试/绘图。
2. 测试通道独立模型在可分块配置下完整推理与分块结果一致；测试跨变量模型只执行完整变量前向。
3. 验收：非法分块/抽样明确失败；图中选择变量不改变预测上下文；旧 HADT 配置仍可运行。

### 阶段C：四个官方主干与分位数适配

1. 固定上游版本、整理许可；按 DLinear→PatchTST→iTransformer→TimeMixer 顺序接入。
2. 每个主干先在 point 模式，使用官方参考模型与本地实现相同权重、输入及归一化设置，对比 eval 数值；测试涵盖本次公开配置分支。
3. 对默认实际使用配置，官方数值保真须通过；未验证分支不得标为支持。上游原代码作为隔离测试参考，不能依赖运行时sys.path注入造成仓库层命名冲突。
4. quantile 模式在四个原生点预测头后追加同一 `MedianAnchoredNonCrossingHead(d_model=1)`；追加前的点模型参数形状必须与point模式一致。检查 `[B,H,C,7]`、有序性、有限loss/梯度及主干、原始预测层、追加头的梯度传播，保存重载一致。
5. 特别检查 TimeMixer 多尺度残差/逆归一化、DLinear 两分支、PatchTST末端padding、iTransformer变量轴token；追加头必须位于完整点预测流程之后，不能重复逆归一化。
6. 验证四个模型复用同一头类而非四份类似实现，公共头不按模型名分支；用 `C != 7` 的输入验证样本/变量/分位数轴还原顺序。配置与来源清单记录 `quantile_adapter=post_point_shared_head`、`head_input_dim=1`、头的追加位置和尺度，HADT另外记录原生D维输入与位置。

### 阶段D：有限端到端验证与交付

1. 在 djjTF 运行迁移回归和新增有意义测试。
2. 四个外部模型各执行一次 ETTh1/H96/seed2024 的短集成试跑，限制训练轮数，用于验证完整链路，明确标为 smoke/integration，不进入正式论文结果。
3. 有限训练子集只能从训练区间截取；测试/验证使用明确记录的检查范围，不把部分测试结果标为完整测试。
4. 额外用高变量数合成输入检查 iTransformer 和 TimeMixer 的通道策略与维度；不以合成输入得分作为实证效果。
5. 验收：5个核心模型入口可构建，四个新增配置可启动；进度、最佳权重、重载、指标、曲线、浏览页均可用；旧实验脚本与旧 HADT检查点回归通过。
6. 更新 README 的目录、运行命令、模型来源和适配说明，提交结构重构及新增模型；正式基准实验另列计划，不假定为本轮完成。

## 11. 关键风险与处理规则

| 风险 | 必须处理的方式 |
|---|---|
| 把本地适配称为官方概率基线 | 使用明确 `-NQ` 标记，保留上游版本和适配差异 |
| 跨变量模型被切变量 | 能力驱动执行；iTransformer强制完整上下文；可视化同样遵守 |
| 迁移改变历史模型或检查点 | 默认计算与参数键不变，固定旧checkpoint做回归 |
| 层文件近似却不等价 | 保留各模型专用层；复用前核对语义与数值 |
| 多尺度/归一化导致量纲或顺序错误 | 完整原生点预测和逆归一化后追加统一头，测试尺度且不重复逆变换 |
| 新代码误复用旧完成缓存 | 身份含配置、模型/输出模式、源码、数据指纹，冲突拒绝覆盖 |
| OOM引发未经声明的结构降级 | 只调整批准的运行资源配置；不能静默拆变量或换主干 |
| 全量实验膨胀 | 首版只接入与有限验证；另列正式训练矩阵和预算 |

## 12. 审核要点
